# ironquill

[![CI](https://github.com/ngodzik/ironquill/actions/workflows/ci.yml/badge.svg)](https://github.com/ngodzik/ironquill/actions/workflows/ci.yml) [![Security](https://github.com/ngodzik/ironquill/actions/workflows/security.yml/badge.svg)](https://github.com/ngodzik/ironquill/actions/workflows/security.yml)

**An experimental terminal coding agent, built around my own way of working. It comes with no guarantee of any kind.**

## Read this first

This is a personal experiment, not a product. It is shaped by my habits and my needs, it changes whenever those do, and it has been tested far less than anything you should rely on.

- **It changes your files without asking.** Edits are written to disk as the model makes them, with no confirmation step. Run it in a git repository, commit before you start, and read every diff it shows you.
- **Watch it closely.** It can misread a request, edit the wrong thing, or keep going on a bad path. Stop it with Ctrl-C the moment something looks wrong.
- **It spends money.** Every request goes to a paid API, within a budget per request that you set. The cost shown is the one the provider reports; when a provider reports none, the total is incomplete, and the interface says so.
- **It has seen little real use.** Around a hundred unit tests, most of the agent loop exercised against a fake server, a handful of sessions with a real model. Used on Linux; on macOS it is only built and tested by CI.

**If you are looking for a coding agent to use, use one of these instead:** [OpenCode](https://opencode.ai), [Pi](https://pi.dev) or [Claude Code](https://code.claude.com/docs/en/overview). They are far more mature, far better tested, more general, and supported by people whose work it is. ironquill overlaps with them on purpose: writing one is how I learn what makes them work and try ideas of my own.

## The idea

Deterministic tools before models. Compilers, tests, linters and git are cheap, fast and right, so they do what they can, and a model is called for the rest. In the conversation a model works as in Claude Code, running the commands it needs; in a pair, checks the planner chose judge the work. Every request shows what it cost.

The interface follows my editor habits: Vim-like modes, a leader key, files opened beside the conversation and edited with Vim keys.

## What it does today

- A conversation in the terminal: questions get answers, requests for changes get edits shown as diffs. As in Claude Code, no check runs on its own: the model runs the project's tests itself when they matter
- Commands, with a safety net. Models run shell commands with a `run_command` tool. A command that cannot be undone, leaves the machine or cannot be read from the command itself is put to you first in a yes or no window: deleting, `git push`, `reset`, `clean`, `rebase`, deleting a branch, `--no-verify`, `sudo`, stopping processes, publishing a package, writing through `gh`, sending data with `curl`, piping into a shell, SQL `DROP` and `DELETE`, overwriting a file with `>`, anything `kubectl` does beyond reading and anything about its secrets or contexts, `eval`, `$(...)`, `sh -c`, `python -c` and decoded text. A command held only because its text does not say what it does is first read by the cheapest model of the team with a known price, which lets it run only when it answers that it only reads. Options such as `kubectl -n web` and queries sent with `curl -G` are read as what they are. The window shows the command in red; `c` copies it. Without the interface, a held command is refused and the model is told not to work around it. Cloud and infrastructure tools are judged the same way: `aws`, `gcloud` and `az` run what only reads (`describe`, `list`, `get`, `ls`, downloads) and ask for the rest; `terraform` and `pulumi` ask before `apply`, `destroy`, `up` or a state change
- Secrets are never shown to a model, and nobody can allow it: reading a file of credentials (`~/.aws/credentials`, `~/.ssh`, `~/.kube/config`, `.env`…), printing the environment or a secret, or asking a secret manager or a CLI for a token (`aws secretsmanager get-secret-value`, `kubectl get secret`, `gh auth token`, `vault kv get`…) is refused outright. Tools find their own credentials: commands run with the environment but its secrets, except those a program reads on its own, such as aws its keys, and files of credentials stay where tools find them. A command run through `aws-vault exec`, `saml2aws exec`, `op run`, `doppler run`, `chamber exec` or `dotenv` is judged as itself, and their exports of credentials are refused. What the project runs, a script in any language, `python -m` a module, a `make` target or an `npm run` script, runs without asking when it is as in the last commit, which you saw; new or changed since, or in a project without git, it is put to you first. Shell scripts, `make` recipes and `npm` scripts are read even then and judged as if typed, so that a committed `make deploy` that syncs to S3 still asks, and they get the keys of the tools they call. `uv run`, `poetry run` and the like are read as the command they run. When an AWS SSO session has expired, the model asks you to run `aws sso login` in your own terminal. A command that names a secret, such as `$API_TOKEN`, asks first, once or for good (`a`); the names allowed are kept in `~/.ironquill/config.toml`, never their values, and `/secrets` lists them or takes one back. Whatever a command prints has the value of any secret replaced by its name. This reads commands as written: it holds what it does not understand, but it is a net, not a sandbox
- What runs code later or decides what is allowed is held: writing to git hooks or `.git/config`, CI workflows, shell start-up files such as `~/.bashrc`, the settings of ironquill, Claude Code or Codex, `git config`, `git -c core.hooksPath=…`, and scheduled tasks. Models' file tools never write inside `.git`. Any program ironquill has no rule for is held too (`/strict off` lets it run). A request to a server neither the project nor your tools already use (its git remotes, your Kubernetes clusters, GitHub, AWS, the package registries) is held, from `curl`, `wget`, `git`, or a name lookup; `a` allows it for good and `/hosts` lists those allowed. Database writes (`UPDATE`, `INSERT`, `ALTER`, `CREATE`, `GRANT`) are held like drops and deletes. Without an OS sandbox this stays a reading of commands: it closes the usual ways out, not every one. Every command a model or an agent runs, or was refused, is written down in `~/.ironquill/audit.log`: when, where, which model, the command, who allowed it and how it ended
- Commands show folded to their first line, with how they ended, who checked them and how much they printed; Enter or a click opens them, `y` copies the selected command or reply
- A model that used all its turns says where its work stands, summed up by the cheapest priced model, and you say whether it goes on; otherwise it answers with what it found. An empty reply is sent back once; twice, you are told
- Pasted text arrives whole: a pasted log is not sent at its first line break
- Stopping a request with Ctrl-C keeps what was done, says so in the conversation, and saves it
- Checks for `ironquill do` and pairs: the project's own, found each time they run (`pytest` or `unittest` when there are Python tests, run with the project's own Python: `uv run` when uv manages it, else its virtual environment, else the Python `pytest` belongs to, and in each directory that is a Python project of its own, such as a `backend`; `npm test`, `cargo check` and `cargo test`), or any command given with `/check`. When the checks fail and nothing was edited since, they are not run again: they would fail the same way
- Escalation from a cheap model to stronger ones when the checks keep failing, for `ironquill do`
- A team: the model that answers may hand a task to another model you picked, a stronger one for a hard change, a cheaper one for a long read, and gets its report back. Ctrl-E searches every model of the provider, with its prices and context; Space puts one in the team
- Scores for every model from [Artificial Analysis](https://artificialanalysis.ai/), with your own free key in `ARTIFICIAL_ANALYSIS_API_KEY`: a coding index and an intelligence index, shown next to the prices and given to the model that hands out tasks. They are kept in `~/.ironquill/rankings.json` and fetched again only when a month old, or when a model you picked is missing
- While a model of the team works on a task handed to it, a sub-agent pane takes most of the screen with its name, the task and everything it does, live; the conversation keeps a third and one line per handover. Ctrl-T hides or shows it
- An effort for models that reason, high unless `/effort`, `--effort` or ← → in the model picker say otherwise: low, medium, high, xhigh or max, shown in the status line. It goes to Requesty as `reasoning_effort` (only for models its list says can reason), to Claude Code as `--effort` and to Codex as `model_reasoning_effort`
- Working in pairs, `/pair <request>`, in three steps: the planner reads the code it needs itself (Claude Code or Codex with their tools, a model of the provider with ironquill's tools that read) and plans, ending with the checks that will judge the work, `Check: <command>` or `Check in <dir>: <command>`, tried once before any change; the coder implements the plan, given in its message; the planner reviews the result from a copy of its planning as it was right after the plan, judging against the request first, and says OK, asks for fixes, changes the checks or stops, four reviews at most. A plan full of code goes back once; a question comes back as an answer. Claude Code's planner starts from a copy of the chat's own session (`--fork-session`, with the chat's very settings, so that it reads the chat's cache), told to read only, and the pair stops if a file changes; `/pair` then goes on from the last pair's session while warm, `/newpair` starts from the chat again. While the coder works, a one word copy of the planner's session keeps its cache warm every four minutes. An agent coder's session lasts from one pair to the next while warm. Pair mode (Tab in the model picker, on when Claude Code is installed): Opus plans and reviews, Sonnet codes. Each step is announced with the model doing it, and a pair ends with one line: who did what, how it ended, what judged it and the files changed
- Instructions, given to every model with each request, read again each time: your own for every project in `~/.ironquill/instructions.md` (`/instructions` opens it in the editor), and those a project already has for coding agents, `CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md` and `.claude/rules/`, with their `@path` imports and the files a rule is scoped to. ironquill reads them and never writes any
- A budget per request, $0.10 unless `/budget` or `--budget` says otherwise: once it is spent the work stops, and the model says what it did and asks what to do next
- Your choices carry over: the model, the models offered, the team and the budget are kept in `~/.ironquill/config.toml` as soon as they change, and every new session starts with them
- Tasks handed to [Claude Code](https://code.claude.com/docs/en/overview) or [Codex](https://github.com/openai/codex) as sub-agents, through the `claude` or `codex` command installed and signed in on the machine: pick a `claude-code/...` or `codex/...` model with Ctrl-E, or send one task with `/claude <task>` or `/codex <task>`. Each keeps its own session for the whole conversation, across model switches and restarts (`/claude-reset` and `/codex-reset` end them), and is told what was said without it since it last took part; a session unused for five minutes, whose prompt cache has expired, is not resumed, as resending all of it would cost more than a new one told the conversation. A new session, or a `/pair` planner, is told the conversation whole, or from a summary and what was said since when it is too long to send whole, so that its start is never lost: the cheapest model of the team with a known price writes the summary then, at a low effort, its cost counted with the request and within the budget; when no summary can be written, the first request is kept with the latest part; what it does shows live. Claude Code, 2.1.281 or later, runs in its own auto permission mode: safe actions run, and what its checks refuse is shown, for you to approve in your next message; with a model that has no auto mode, such as Haiku, it edits files and runs no command, and says so. Agents are told to do what was asked and nothing else. Codex runs its commands in its own sandbox, writing inside the project only and without network. Files changed by commands are found from the project before and after
- Reading little: models find code with `search` (as ripgrep, skipping what git ignores) and `outline` (the functions, classes and types of a file or directory, parsed with tree-sitter for Rust, Python, TypeScript and JavaScript), then read a range of lines rather than whole files
- Compaction: past 40k tokens, or half the model's context, the results of old tool calls are dropped all at once, down to half that, so the conversation is resent shorter and the provider's cache can take over again
- Caches kept warm: `/tick` reads Claude Code's warm sessions, the chat's and the last pair's, every four minutes while you think, with the very settings of their last call, so that the next request reads them from the cache; after half an hour without a request it asks whether to go on. When a conversation's cache has expired anyway, a window asks: start again from its summary, go on as it is (saying how many tokens that writes), or stop, to compact first
- `/compact`: the conversation is cut into exchanges, the cheapest priced model groups them by subject from their titles, and a window lets you untick a subject or a single exchange and keep the last one as it was; what is kept is summed up, and the agents start again from the summary
- A cold cache costs less: when a provider's model answers in a conversation left unused longer than its provider keeps a prompt cache, half an hour for Sference and five minutes elsewhere, the history before the last two requests is replaced by the summary, if it holds over 20k tokens and a fifth at least is saved
- Claude Code's and Codex's cost as they work: each message Claude Code ends, and each call Codex logs in its session file (`~/.codex/sessions`, as ccusage reads it), is priced with [LiteLLM](https://github.com/BerriAI/litellm)'s public price list (see [Data from others](#data-from-others)), as ccusage does, kept a week in `~/.ironquill/prices.json`; on an API key the cost is owed, shows live and counts against the budget; Claude Code's own total, which covers its whole session, fills in only for a new session whose messages could not all be priced; on a subscription it shows as such. Whether Codex is billed comes from `codex login status`; its credentials are never read
- Cost, tokens and how full the context is, per request and for the whole conversation; an agent's context shows as it works once its window is known
- `/usage` or Ctrl-O shows a pane of the last hour, `/usage 6h` or Ctrl-P another window, kept for the next session: each model's cost added up, the conversation's context, the calls that rebuilt their cache, and per model its calls, cost and how much it read from the cache, when the provider says. It is kept with the conversation for a day
- The context in your hands: `/context` opens what the next request will send in the Vim editor, to delete passages, shorten tool results or add notes; `:w` applies it. Long replies fold, and Ctrl-Z gives the conversation the whole screen
- Code in replies: each code block has a copy mark (⧉) a click copies it with; `path:line` references, files and commits are links that open the file at that line, showing what the branch changed (Option with ↓ or ↑ goes from change to change); `diff` blocks are coloured. `/address <pr>` reads a pull request's review comments with `gh` and answers each with what it asks, whether it is handled, the change as a numbered diff and a reply to copy; `/apply 1 3` applies the chosen diffs with `git apply`, all or none
- Images in replies, in Kitty (on Linux and macOS, tmux included with `allow-passthrough on`): a line that is only `![what](path.png)` shows the PNG, transparency kept; ```` ```mermaid ```` blocks show as diagrams, drawn by [mermaid-cli](https://github.com/mermaid-js/mermaid-cli) (`mmdc`) or [`mmdr`](https://github.com/1jehuang/mermaid-rs-renderer) when installed, and kept in `~/.ironquill/cache/diagrams`; a click on a cited `.png` shows it. The terminal is recognised when ironquill starts; `images = "kitty"` in `~/.ironquill/config.toml` forces Kitty's protocol in a terminal that speaks it but is not recognised, `images = "off"` shows none, and `mermaid = ["…", "{input}", "{output}"]` sets what draws diagrams (`[]`: nothing). Elsewhere, images and diagrams stay text
- A long reply folds from its fold line only, the latest staying open; the terminal's title is the conversation's name
- `/copy` opens the conversation as text in the editor, to select with `v` or `V` and copy with `y` to the system clipboard; Shift and the mouse select on screen in most terminals
- Conversations saved locally and resumed with `ironquill -c`, `/resume`, or by id with `/resume <id>` or `ironquill -r <id>`
- A file tree, an open file coloured by language and editable with Vim keys (visual mode, registers including the system clipboard, `:s`, search)
- A pane listing running Docker containers
- A window, in progress: `ironquill --gui` draws the same conversation on the GPU, with Bevy and egui, the same keys and commands, the windows that ask, the file tree and the open file, and the usage pane (Ctrl-O) as charts you can hover, drag and zoom. Ctrl-N opens the plan: the codebase's design, flat, one level at a time, its parts (packages found by their manifests, folders, files) as cards in layers with the foundations at the bottom, each link what one uses of another, thicker for more imports and red when it closes a loop; tests, documents and examples are left out of it. A folder of many packages (`providers/`) is one card: double-click a card to open it onto its own parts, and the way back is at the top. Point at a part to light what it uses and what uses it, click it for its files, and a part ripples as the agent reads it and flares as it edits it. A front end that calls its back end through an OpenAPI spec is linked to it in magenta: each operation of the spec (`operationId`) to the function serving it under a route decorator, and to the front end's files calling it by the names generated clients give it (`useDagServiceGetDag`); in Airflow, the React UI to the FastAPI routes, 298 files. Large monorepos are read whole, away from the window (Airflow's 14,000 files in about a second), Python's absolute imports across packages and TypeScript's path aliases (`tsconfig.json`) included. Ctrl-N again opens the API: every route of the project's OpenAPI specs, grouped by tag, its method in colour and its parameters lit, to filter by method; the routes the front end calls most as bars; and for a route chosen, its way through, drawn: the front end's files that call it, the route, the back end's function that serves it, each a click from open, the function at its line. Ctrl-N a third time opens the universe: the codebase in 3D, each file a star coloured by its language and sized by its length, linked to its folder and to what it imports, spreading out as the layout finds its places; a file the agent reads lights up, one it edits flares with sparks; drag to turn, scroll to come closer, click a star to centre it, double-click to open it. Ctrl-M makes it see-through, as a terminal can be, and back; it is kept for the next session, and `opacity = 0.7` in `~/.ironquill/config.toml` sets how much (with a compositor, on X11) Pictures, diagrams, Docker and the sub-agent pane are still the terminal's
- Any OpenAI compatible endpoint, Requesty by default

## What it does not do

- Ask before writing a file, or before a command it does not hold
- Stream answers as they are written
- Run on Windows, or on macOS beyond what CI builds and tests
- Sandbox the check commands: they run as you configured them

## Usage

```bash
export IRONQUILL_API_KEY=...        # your provider key; without one, only Claude Code and Codex answer
cd your-project
ironquill --model <cheap-model> --escalate <strong-model>
```

`/help` lists the commands, Ctrl-S every shortcut. Up and Down in the message box go through the messages sent before, as in a shell. `IRONQUILL_BASE_URL` points it at another OpenAI compatible endpoint. `IRONQUILL_MODELS` (comma separated) lists the models Ctrl-E offers; `claude-code/opus` and `claude-code/sonnet` are added when the `claude` command is installed.

## Building

On Linux the window needs Wayland's client library to build: `sudo apt install libwayland-dev` on Debian and Ubuntu.

```bash
cargo install --path .              # builds the ironquill binary into ~/.cargo/bin
scripts/check.sh                    # what CI runs: formatting, lints, docs, tests, dependency audit
git config core.hooksPath .githooks # run those checks before every commit
```

## Data from others

ironquill ships none of the data below. Each install fetches it for its own use, keeps a copy on the machine, and says where it comes from.

- **Model prices** for Claude Code's and Codex's calls come from [LiteLLM](https://github.com/BerriAI/litellm)'s public list, [`model_prices_and_context_window.json`](https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json), under the MIT licence. They are list prices: an estimate of what a message costs, not a bill. [ccusage](https://github.com/ccusage/ccusage) prices Claude Code's usage from the same list.
- **Model scores** come from [Artificial Analysis](https://artificialanalysis.ai/)' free API, with your own key, under their terms, which ask that they be credited; the model picker does so wherever scores show.
- **Model lists, prices, context windows and descriptions** for the provider's models come from the provider itself, such as Requesty's `/v1/models`.
